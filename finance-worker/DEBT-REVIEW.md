# หนี้: ยอดรวมค้างชำระและการแจกแจงจากใบแจ้งยอด

เจ้าของยืนยันเมื่อ 3 พฤศจิกายน 2569: ยอดหนี้คงเหลือรวมเงินต้น + ดอกเบี้ยค้าง + ค่าธรรมเนียมค้าง และกรอกแยกตามใบแจ้งยอด/หลักฐานจริงแต่ละครั้ง

## สิ่งที่ทำในระบบใหม่

- เพิ่มเจ้าหนี้ด้วยยอดค้างเริ่มต้นทั้งสามส่วน ระบุวันที่และแหล่งอ้างอิง ไม่มีส่วนใดต้องกรอก 0 อย่างชัดเจน
- ชำระโดยระบุเงินที่ออกจากบัญชีจริงและส่วนที่ตัดเงินต้น/ดอกเบี้ย/ค่าธรรมเนียม ผลรวมต้องตรง และแต่ละส่วนห้ามเกินยอดค้างของส่วนนั้น
- เก็บธุรกรรมบัญชีเพียงรายการเดียวตามยอดจ่ายรวม ส่วนแจกแจงเก็บในรายการหนี้ที่เชื่อมรหัสเดิม VOID หลัง baseline ล่าสุดคืนยอดทั้งบัญชีและส่วนประกอบร่วมกัน
- ดอกเบี้ยหรือค่าธรรมเนียมค้างรอบใหม่ไม่เกิดจากสูตรอัตโนมัติ ปุ่มปรับยอดหนี้ใช้ยืนยันยอดค้างทั้งสามส่วนตามใบแจ้งยอด ณ วันที่ระบุ เป็นรายการ `STATEMENT` พร้อม audit และอ้างอิง โดยไม่สร้างการจ่ายหรือเปลี่ยนเงินในบัญชี
- การเพิ่มหนี้หมายถึงเพิ่มเงินต้นตามฟีเจอร์เดิม ไม่สร้างเงินเข้าบัญชีแทนเจ้าของ
- รายเดือนยังหมายถึงยอดที่ยังต้องจ่าย ณ ตอนตั้งค่า ใช้ `paid_at_setting` และเก็บประวัติแผนเดิม ไม่ถือว่าดอกเบี้ยค้างเท่ากับดอกเบี้ยอนาคต
- ยอดที่จ่ายครบทั้งสามส่วนเป็น 0 จะซ่อนจากรายการหนี้ แต่ประวัติยังอยู่ หนี้เดิมที่ยังไม่ยืนยันส่วนประกอบต้องยังมองเห็นได้แม้ legacy total เป็น 0

## ประวัติเดิม

`debtBalance_` ของ v53 ลบ PAYMENT ทั้งจำนวน และไม่มีส่วนประกอบค่างวด การนำเข้าจึงเก็บตัวเลขเดิมไว้สำหรับความต่อเนื่องแต่ไม่สมมติว่าเป็นเงินต้น ไม่แปลง `total_interest` เก่าหรือดอกเบี้ยที่ไม่ได้กรอกให้เป็นอัตรา 0% และไม่แก้ประวัติย้อนหลัง

เมื่อเจ้าของมีใบแจ้งยอดจริง สามารถยืนยันยอดค้างล่าสุดทั้งสามส่วนเป็น `STATEMENT` แล้วใช้ baseline นั้นกับรายการใหม่ต่อ ประวัติก่อน baseline ยังอยู่ครบ ยอดก่อนหน้านั้นยังไม่ได้รับการรับรองย้อนหลัง ไม่แก้เงินในบัญชี ไม่สร้างค่างวดเก่าซ้ำ

ปฏิเสธการลงวันที่ก่อนรายการหนี้ล่าสุด และการ VOID payment ที่มีใบแจ้งยอด baseline ภายหลัง เพื่อให้ทบทวนประวัติก่อนเปลี่ยนยอดย้อนหลัง ไม่เขียนสูตรชดเชยเอง

## เอกสารตัวอย่าง

ตรวจภาพตัวอย่างยูเมะพลัสทั้งสองฉบับแล้ว ตัวอย่างแยกเงินต้น ดอกเบี้ย และค่าธรรมเนียม และมีความต่างของวันสรุปบัญชีกับวันจ่าย รวมถึงยอดที่ยังไม่เรียกเก็บ จึงไม่ใช่หลักฐานอัตรา/ยอดจริงของเจ้าของ ไม่คัดลอก PDF, ภาพหรือข้อมูลจากเอกสารเข้า GitHub และไม่ฝังอัตราตัวอย่างในระบบ ไม่มีการคำนวณรายวัน, billed/unbilled accrual หรือประเมินยอดปิดหนี้ในรุ่นนี้

## ข้อจำกัดที่ต้องเห็นบนหน้าจอ

ยอดรวมที่แสดงคือผลของข้อมูลที่ผู้ใช้ระบุ ณ baseline และรายการหลังจากนั้น ไม่อัปเดตดอกเบี้ยเองเมื่อเวลาผ่านไป และไม่ใช่ยอดปิดหนี้ในอนาคต การยืนยันตัวเลขกับใบแจ้งยอดจริงเป็นอีกขั้นหนึ่ง ไม่ถือว่า local test หรือการนำเข้าผ่านเป็นการยืนยันหนี้จริง
