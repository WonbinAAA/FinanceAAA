# แผนย้ายข้อมูลโดยรักษาประวัติ

เจ้าของเลือกเริ่มฐานใหม่แล้วนำเข้าประวัติภายหลัง เครื่องมือจึงต้องไม่เติมประวัติเก่าทับยอดเริ่มต้นหรือบัญชีที่เริ่มบันทึกไปแล้วโดยอัตโนมัติ

## ระหว่างพัฒนา

ใช้ข้อมูลจำลองเท่านั้น ทั้ง schema และ source repository ไม่มีบัญชี ยอดเงิน หรือประวัติจริง ทดสอบบน local D1 ก่อน แล้วใช้ฐาน preview แยกเมื่อเชื่อมบัญชี Cloudflare สำเร็จ เก็บเว็บเดิมเป็นแหล่งใช้งานจริงจนกว่าจะตกลงเปลี่ยนระบบ

## ส่งออกต้นทางในอนาคต

`scripts/ExportForD1.gs` เป็น helper ที่ยังไม่ได้เพิ่มหรือ deploy เข้า Apps Script ตัวเดิม เมื่อพร้อมย้าย ให้นำไปใช้กับโปรเจกต์เดิมแล้วรัน `downloadFinanceForD1` จาก Script editor ของชีต มันอ่านอย่างเดียวและเปิดหน้าต่างให้ดาวน์โหลด JSON ไม่สร้างธุรกรรม ไม่แก้ Sheet ไม่ log ข้อมูล และไม่บันทึกไฟล์ลง Drive เอง

รูปแบบ `finance-sheets-v1` เก็บหัวตารางเดิม, `_row` ต้นทางตั้งแต่แถว 3, รหัสทุกประเภท, สถานะ ACTIVE/VOID/DRAFT, วันที่, ลิงก์ระหว่างธุรกรรม, ประวัติ audit, แผนรายเดือน, recurring, claims, matches และ projects พร้อมผลรวม `expected` ของต้นทาง ณ snapshot เดียวกัน

เก็บ export/backup/report จริงไว้ใต้ `private/`, `imports/`, `backups/`, `reports/` ที่ถูก ignore หรือที่เก็บส่วนตัวภายนอก repository ห้าม commit หรือเพิ่มเป็น build asset

## ตรวจแบบไม่เขียนข้อมูล

```powershell
npm run import:check -- private\finance-sheets-export.json reports\import-review.json
```

CLI อ่านไฟล์ในเครื่อง ไม่เรียก Sheets, Cloudflare หรืออินเทอร์เน็ต และไม่พิมพ์ยอดเงินจริงออก console หน้าจอ `/migration` รองรับ preview, เทียบยอด, ตรวจ D1 ปัจจุบัน และดาวน์โหลด backup

ระบบตรวจรหัสซ้ำ, หัวตาราง, จำนวนเงินทศนิยมสองตำแหน่ง, วันที่จริง, ความเชื่อมโยง, ลำดับแถว และเงินบริษัทที่ต้อง replay ตามลำดับเดิม เปรียบเทียบยอดรายบัญชี/เงินสด/เงินพร้อมใช้/เงินเข้าออก/ยอดเริ่มต้น/ค้างคืนบริษัท/ล่วงหน้า/กองกลาง/โปรเจกต์ ไม่มีการเปลี่ยนรหัสหรือเลือกจับคู่ใหม่

ไฟล์เดิมที่นำเข้าซ้ำจะ skip เมื่อข้อมูลเหมือนกัน รหัสเดิมแต่ข้อมูลต่างกันหรือแถวชนกันจะหยุด การ commit ต้องมี `expected` ตรงทุกช่อง, digest และ revision ตรงกับผล preview และผู้ใช้พิมพ์ยืนยัน ไม่อาศัยแค่สมการยอดเงินรวมที่ตรงกัน

## เมื่อนำเข้าหลังเริ่มใช้ฐานใหม่

เครื่องมือจะหยุดด้วย `USED_DATABASE_REQUIRES_OPENING_BALANCE_PLAN` หากมีข้อมูลใช้งานแล้วและกำลังจะเพิ่มประวัติใหม่ นี่คือจุดที่ต้องให้เจ้าของเลือกบัญชี/รหัสที่จะใช้ต่อ วันตัดยอด และว่าจะใช้ยอดยกมาหรือประวัติเต็ม ต้องวางแผนและทดสอบกับสำเนาก่อน ไม่แปลง/รวม/ลบข้อมูลเดิมเพื่อให้ผ่านเอง

วิธีที่เตรียมไว้สำหรับการย้ายประวัติเต็มคือทดสอบนำเข้าในฐานว่างอีกฐาน แล้วเทียบกับข้อมูลทั้งสองฝั่งก่อนสร้างแผนรวมข้อมูลที่เจ้าของยืนยัน หากไม่เลือกนำประวัติเก่ามาคิดยอด อาจจัดเก็บเป็นประวัติสำหรับอ่านอย่างเดียว แต่ยังไม่ได้ implement/เลือกพฤติกรรมนี้

## หนี้และการเปลี่ยนเว็บหลัก

ยอดหนี้เก่าที่หักค่างวดทั้งจำนวนจะเก็บไว้ตามเดิมพร้อมสถานะ `NEEDS_STATEMENT_REVIEW` แม้ยอดเงินสด/บริษัทตรงทั้งหมดก็ยังไม่ถือว่าหนี้ถูกต้อง ต้องบันทึกเงินต้น ดอกเบี้ยค้าง ค่าธรรมเนียมค้าง และวันที่จากใบแจ้งยอดจริงเป็น baseline ใหม่ โดยไม่แก้ค่างวดเดิมหรือเงินในบัญชี ดู DEBT-REVIEW.md

การตรวจของโปรแกรมเป็นการตรวจความสอดคล้องและเทียบ snapshot ไม่ใช่การรับรองกับธนาคาร ช่อง `financial_verified` จึงคง false ต้องตรวจยอดภายนอกจริงและการเข้าใช้งานจริงก่อนตกลงเปลี่ยนเว็บหลัก ไม่สร้างธุรกรรมเงินจริงเพื่อทดสอบ ไม่เปิด sync สองทางระหว่างระบบเก่ากับใหม่
